# Драфты, фичи и локальный CLI задач

Фича: [F20 — planning loop](./README.md). Развивает [F11](./../f11-git-task-pipeline/README.md),
согласуется с [F22](./../f22-git-trunk-review/README.md).
Требования: [целевой процесс](./../AGENT_WORKFLOW.md).

## Что сделать

- [ ] Определить Markdown/YAML-контракт фичи и отдельных задач под `.tasks/`: цель, критерии,
      поручения, `parent`, зависимости, сжатая память, прогресс, проблемы и ссылки на review.
- [ ] Валидировать неизвестные зависимости, циклы и границы делегирования; отделить изменение
      поручения от обновления памяти и Git HEAD. Не хранить ID runtime-исполнителей и ACP-сессий.
- [ ] Предоставить локальный `taskd` CLI внутри каждого агентского контейнера: только файлы,
      без Git push, подписки на meshbus и запуска исполнителей. Спроектировать миграцию прежней
      host-reconciliation логики в `agentd`, не поддерживая две конкурирующие модели запуска.
- [ ] Root сохраняет сжатое обсуждение в опубликованной ветке драфта. Явная команда человека
      переводит его к отдельному planner; появление драфта само по себе ничего не запускает.
- [ ] Planner формирует иерархию задач в пределах требований. Создание review-задач и их права
      определяет системная политика. Требования меняет только root по решению человека.
- [ ] Агент публикует локально подготовленные изменения Git-инструментами через F22; прогресс
      отделяется от кода, а `taskd` не реализует Git-транспорт или approval.

## Критерий готовности

- [ ] Драфт загружается новой сессией, валидный план сохраняется через принятый Git-интерфейс,
      некорректная иерархия отклоняется; до команды стартовать нет выполнения.
- [ ] Смена контейнера сохраняет логическую задачу и её память без переноса runtime identity.

## Проверки и миграция

Контракты CLI и parser, совместимость/явная миграция старого формата, цикл и неизвестная ссылка,
обновление памяти без перепланирования. Политика тестов — в [tests/README.md](./../../tests/README.md).
