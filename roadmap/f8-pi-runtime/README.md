# F8. Интерактивный Pi runtime

Pi — основной harness разработки на NixOS-ноде. Его runtime, конфигурация моделей и набор
tools едины для интерактивной работы и будущего stateless-режима workers. Локальный Pi TUI по
решению не используется: и интерактивная работа, и RPC-доступ для будущих workers идут через
один ACP-путь.

Отдельная интерактивная ветка публикует тот же Pi runtime как постоянный сетевой ACP daemon: один
endpoint обслуживает динамические параллельные сессии и позволяет нескольким клиентам подключаться
к одной live session. Эта ветка не меняет disposable-модель будущих workers.

Зависит от [F7](../f7-llm-gateway/README.md). Соответствует
[вехе 8](../VISION.md#вехи-и-зависимости-без-деталей).

**Статус:** все задачи F8 закрыты (f8-01…f8-06). f8-04 и f8-05 закрыты по решению «Pi TUI не
используется, работа идёт через ACP»: интерактивная acceptance выполнена через ACP, отдельного
Pi-native RPC-контракта нет — роль RPC entry point для F10 выполняет ACP endpoint из f8-06.

**Критерий готовности:** после декларативного rebuild пользователь работает с логическим классом
модели и выполняет реальную задачу с `bash/git/tools` через ACP-клиента (Ferngeist) — Pi TUI не
используется, интерактивная работа ведётся через ACP; provider-specific настройки в Pi
отсутствуют; сетевые ACP-клиенты через один endpoint создают параллельные сессии и подключаются к
общей live session, а тот же runtime имеет проверенный RPC entry point для F10 — им служит
закреплённый ACP endpoint (f8-06), отдельный Pi-native RPC-контракт не вводится.

**Осознанно откладываем (до F10):** unattended execution, sandbox и жизненный цикл worker.
