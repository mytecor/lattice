# F23. Распределённая координация

Отдельный слой кворумного согласования на доверенных физических нодах поверх существующего
meshbus/RNS. Единственный постоянно назначенный `agentd` не допускается; r1s остаётся сервисом
контейнеров без знания фич, задач и reviewer.

Соответствует [вехе 23](./../../ROADMAP.md#f23-распределённая-координация).
Согласованные требования — в
[AGENT_WORKFLOW.md](./../AGENT_WORKFLOW.md#распределённая-координация-и-recovery).
Зависит от [F2](./../f2-secrets-identity/README.md), [F3](./../f3-reticulum-tcp/README.md) и runtime
границы [F19](./../f19-agent-execution-loop/README.md). Принятие trunk согласуется с
[F22](./../f22-git-trunk-review/README.md), multi-agent — с [F21](./../f21-multi-agent/README.md).

**Статус:** требования согласованы, реализация не начата. Библиотека консенсуса, storage и
точный протокол назначения/принятия ещё не выбраны.

## Задачи

- [f23-01](./f23-01-consensus-protocol.md) — выбрать основу консенсуса и испытать membership,
  право исполнения, r1s lease и взаимодействие с trunk.

## Согласованные ограничения

- Один кластер на realm, общий meshbus realm и список разрешённых identity физических нод.
  Временные контейнеры не голосуют только на основании знания realm key.
- Все доверенные физические ноды — участники; одинаковый начальный список identity задаётся
  конфигурацией. Дальнейший состав меняется протоколом, а не обновлением списка видимых peers.
- Новая нода сначала догоняет состояние; удаление длительно недоступной ноды может автоматически
  согласовать текущее большинство. При отсутствии большинства состав не уменьшается.
- Разрешён старт с одной ноды; большинство: 1/1, 2/2, 2/3. Потеря большинства останавливает
  новые согласуемые решения, но не создаёт независимый кластер в каждой части сети.
- Без подтверждённого права `agentd` прекращает продление r1s run. Существующий runtime lease
  исполняет остановку на работающем `r1sd`; повторный lease контейнера не добавляется в Lattice.
- Контекст и готовность задач восстанавливаются обходом Git, не реестром активных ACP-сессий.
  Хранение служебного состояния консенсуса не подменяет Git-состояние фич/задач.

## Критерий готовности

Воспроизводимы начальный состав, расширение, исключение, рестарт, partition и потеря большинства.
Передача прав учитывает последнее допустимое продление r1s lease и возвращение прежнего владельца.
Межнодовая корректность принятия trunk доказана с F22, а не выведена из одного локального rebase.
