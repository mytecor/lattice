# Принять проверенный результат задачи в trunk

Фича: [F22](./README.md). После выбора backend в [f22-01](./f22-01-backend-selection.md);
распределённый контракт согласуется с [F23](./../f23-distributed-coordination/README.md).

## Что сделать

- [ ] Интегрировать выбранный backend на каждой физической ноде. Review/checks передавать
      через интерфейс Lattice: сервис проверяет согласованное F23 назначение reviewer/checker,
      долговременные credentials backend остаются на хосте. Проверить запрет прямого push,
      самоодобрения, чужого назначения и обхода checks.
- [ ] Запускать проверки точного кандидата в отдельном контейнере: принятый минимум репозитория
      плюс проверки задачи. Автор изменения не может ослабить их тем же кандидатом.
- [ ] Сохранять review/check evidence в Git и принимать отдельные служебные изменения состояния
      через полномочия интеграции Lattice; не разбирать задачи универсальным ядром принятия.
- [ ] Автоматически пробовать rebase; конфликт публиковать как результат обработки предложения
      для его автора. После обновления кода повторять checks/review до принятия.
- [ ] Проверить случай, когда изменилось только служебное состояние: approval остаётся применимым
      без подмены проверенного кода, требований или политики.
- [ ] Через F23 согласовывать переход ожидаемый SHA → точный итоговый SHA единого `main`,
      затем идемпотентно применять локальный ref. Без большинства принятия ждут.
      Принимать задачу одним коммитом. С F23
      испытать два конкурентных приёма на разных нодах, сбой между решением и обновлением ref,
      запаздывающую репликацию и возвращение старого экземпляра сервиса.
- [ ] Воспроизвести процесс без Radicle, затем с подключённой репликацией. Служебные refs не
      считать реплицируемыми автоматически без проверки выбранного транспорта.

## Критерий готовности

- [ ] В `main` попадает только принятый кандидат; повторная обработка не дублирует принятие.
- [ ] История review восстановима из Git; остановка одного процесса не требует иной review DB.
- [ ] Приём не зависит от `rad review`, runtime ID в файлах задач и постоянной root-сессии.
