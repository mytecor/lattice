# F22. Git review и trunk

Контролируемое принятие результатов задач в `main`: рабочие ветки, независимый reviewer,
отдельные checks и один итоговый коммит задачи. Хранилище кода и ценных review-метаданных — Git.
Сервис принятия не знает структуры фич и задач; Radicle — сменяемая репликация, а не обязательный
review backend.

Соответствует [вехе 22](./../../ROADMAP.md#f22-git-review-и-trunk). Требования — в
[AGENT_WORKFLOW.md](./../AGENT_WORKFLOW.md#git-review-и-принятие).
Использует контейнеры [F10](./../f10-disposable-worker/README.md); распределённая приёмка
проектируется совместно с [F23](./../f23-distributed-coordination/README.md).

**Статус:** не начата. Gerrit обсуждён как готовая альтернатива собственному `merged`, но выбор
ещё не сделан. Не создавать параллельные review-системы и не привязывать контракт к `rad review`.

## Задачи

- [f22-01](./f22-01-backend-selection.md) — PoC Gerrit против минимального Git-only приёма,
  выбор backend и контракт интеграции Lattice;
- [f22-02](./f22-02-trunk-acceptance.md) — интеграция и приёмка пути ветка → review/checks → trunk.

## Критерий готовности

- Агент локально работает обычным Git, публикует предложение, но не пишет прямо в `main`.
  Reviewer действует отдельными ограниченными credentials, самоодобрение не принимается.
- Approval передаётся операцией над конкретной версией кандидата и сохраняется в Git вне файлов
  задач. Checks публикуются независимым исполнителем; review не теряется при смене репликации.
- Кандидат переносится на актуальный trunk автоматически; конфликт возвращается автору.
  Изменение кода требует новой проверки, одни служебные коммиты задач не вызывают бесконечного
  сброса approval. В `main` оказывается проверенный результат задачи одним коммитом.
- Права публикации состояния и делегирования проверяет интеграция Lattice, не универсальное
  Git-ядро. Политику репозитория меняют только после подтверждения человека.
- Локальная атомарность bare ref и межнодовое согласование различены и испытаны совместно с F23.

## Открытые решения

Выбор backend, выдача и отзыв credentials, привязка прав reviewer к change, хранение checks,
определение exact candidate, автоматическое принятие служебных изменений и распределённое
развёртывание. Вариант Gerrit требует оценить его аккаунты, ACL, NoteDb и HA, а не считать его
обычным stateless hook поверх независимо реплицируемых bare-репозиториев.
