# Выбрать Git review/trunk backend

Фича: [F22](./README.md). Целевой процесс — [AGENT_WORKFLOW.md](./../AGENT_WORKFLOW.md).

## План PoC (2026-11-03)

Первым испытывается Gerrit; собственный сервис рассматривается только при конкретном
несоответствии требованиям или чрезмерной сложности интеграции. PoC изолирован от production
`main` и текущего pipeline. Реализацию консенсуса выбирает F23; здесь определяется и испытывается
необходимый контракт. Заглушка координации не считается доказательством распределённой корректности.

- [ ] Поднять изолированный Gerrit на закреплённых версиях; проверить загрузку change,
      patch sets, независимые Code-Review/Verified, отзыв/устаревание approval и submit.
- [ ] Проверить подготовку одного коммита задачи, Change-Id и отдельное сохранение рабочей
      истории/checkpoints. Не рассчитывать на автоматический squash произвольной ветки Gerrit.
- [ ] Испытать интерфейс Lattice для review/checks: сервис ноды проверяет назначение F23,
      роль и точного кандидата, затем записывает решение в Gerrit. Проверить повторный запрос,
      отзыв доступа, чужое назначение, самоодобрение и обход checks/прямой push в `main`.
      Долговременные credentials Gerrit не передавать контейнерам.
- [ ] Определить операции публикации review/checks и принятия с ожидаемым и итоговым SHA,
      аутентификацию, идемпотентность и ответы при устаревшем кандидате. Не закреплять API
      собственного backend до выбора Gerrit или отказа от него.
- [ ] На трёх экземплярах совместно с F23 проверить общее согласование до обновления refs:
      два конкурентных кандидата, partition 2+1, отсутствие большинства, сбой после решения
      до обновления ref, продолжение другой нодой и возвращение устаревшего экземпляра.
      Не допускать двух принятых вершин; повторное исполнение не создаёт новое принятие.
- [ ] Проверить доступность итоговых Git-объектов, задержку репликации и восстановление
      review из Git. Воспроизвести обычным Git-транспортом, затем через Radicle; необходимые
      служебные refs не считать реплицируемыми автоматически.
- [ ] Проверить rebase на новый `main`, возврат конфликта автору и повторные review/checks
      изменённого кандидата. Допустимые изменения памяти задачи сохраняют применимость approval,
      если результат, требования и политика не изменились.
- [ ] Спроектировать интеграцию задач вне Git-ядра: автоматический приём допустимого
      состояния, системное создание review-задач и подтверждение изменений политики человеком.
- [ ] Зафиксировать ADR: поддержанные требования, адаптеры, зависимости, лицензии,
      эксплуатационные затраты и дальнейшие задачи. При отказе от Gerrit привести
      воспроизводимую причину и требования к небольшому Git-only `merged` с review state в Git.
- [ ] Обновить связанные документы и архитектурные диаграммы; проверить ссылки через `lychee`.

## Критерий готовности

- [ ] Воспроизводимый PoC и явный выбор backend; ограничения не скрыты за успешным single-node submit.
- [ ] Единый принятый `main`, восстановление незавершённого принятия, независимость review/checks
      и проверка полномочий подтверждены указанными сценариями.
- [ ] Review остаётся проверяемым после завершения запуска и отзыва доступа; отдельная
      авторитетная review DB и Radicle-specific API не требуются.
