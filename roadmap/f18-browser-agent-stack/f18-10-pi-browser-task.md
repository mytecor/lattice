# f18-10. Интерфейс для Pi: `browser_task`

## Контекст

После стабилизации браузерного runtime подключить Jev как tool к Pi. Pi не должен видеть
десятки browser primitives — основной abstraction один tool `browser_task`.
Задача запускается целиком в Jev (свой decision loop), Pi не вмешивается.

## Что сделать

- [ ] Tool `browser_task` с параметрами:
      ```text
      url
      goal
      ```
      (опционально позже: `session_id`, `record`, `screenshots`).
- [ ] Вызов запускает оригинальный `Agent(url, goal)` из `jev-ultrafast`
      (без fork и без своей policy).
- [ ] Pi передаёт задачу целиком; Jev сам выполняет decision loop и возвращает результат.
- [ ] Подключить tool к Jev-обёртке/сервису на ноде так, чтобы это не раскрывало наружу
      browser primitives.
- [ ] Проверить вызов из Pi реальной browser-задачей (можно использовать ту же страницу,
      что в f18-04/f18-11).

## Критерий готовности (Definition of Done)

- [ ] Один tool `browser_task(url, goal)` доступен Pi; вызов закрывает полноценную задачу.
- [ ] Jev работает без локальных изменений (upstream).

## Затрагиваемые файлы / слои

- Jev-обёртка / tool-интерфейс для Pi (там, где живут tools Pi в этой вертикали).
- `profiles/pi/*` может расширяться только tool-контрактом, не browser primitives.

## Открытые вопросы

- Механика подключения tool к Pi (какой runtime/протокол у Pi tools в этой ветке;
  как передаётся результат Jev обратно) — по фактическому состоянию F8/F10.
