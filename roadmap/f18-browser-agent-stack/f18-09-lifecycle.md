# f18-09. Lifecycle и восстановление

## Контекст

Foxbridge/Camoufox — отдельный long-running runtime. Нужно убедиться, что его падение
не роняет весь стек и что состояние корректно восстанавливается. На первом этапе —
**один** Camoufox instance, без pool и autoscaling.

## Что сделать

- [ ] Проверить восстановление после падения Camoufox (Foxbridge пересоздаёт браузер?).
- [ ] Проверить восстановление после падения Foxbridge (сервис поднимается, harness
      переподключается).
- [ ] Проверить повторное подключение `browser-harness` после перезапуска рантайма.
- [ ] Проверить отсутствие zombie browser processes (kill Camoufox → нет осиротевших).
- [ ] Проверить корректное закрытие target после `Agent.close()`.
- [ ] Проверить, что падение Jev не завершает browser runtime некорректно (сервис Jev
      может упасть — runtime остаётся жив и переиспользуем).

## Критерий готовности (Definition of Done)

- [ ] Все перечисленные сценарии воспроизведены и восстановимы (или зафиксирован
      воспроизводимый лимит с указанием, где чинить).
- [ ] Нет zombie процессов; `Agent.close()` закрывает target.

## Затрагиваемые файлы / слои

- `modules/services/foxbridge-camoufox.nix`, `modules/services/jev-ultrafast.nix`
  (restart-политики юнитов, `Restart=`, readiness/healthcheck).
- Возможные минорные правки Foxbridge при необходимости.

## Открытые вопросы

- Ожидаемое поведение «после падения Camoufox»: поднимать ли новый instance сразу или
  ждать следующего обращения Jev — решается по фактическому поведению Foxbridge.
