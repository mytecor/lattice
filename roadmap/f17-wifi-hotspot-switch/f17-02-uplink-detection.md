# f17-02. Обнаружение проводного аплинка и триггер переключения

Событийный механизм, который определяет, есть ли у ноды **проводной default-route в интернет**, и
запускает переход в `ap` (или обратно в `client`).

Движет [F17 — динамический режим ноды: Ethernet → Wi-Fi точка доступа](./README.md).

## Контекст

Триггер — не «кабель вставлен», а «по проводу есть реальный default-route». Обычно провод вставлен
раньше, чем аплинк получает интернет, поэтому на одно событие кабеля может приходиться несколько
изменений маршрутов.

## Что сделать

- [ ] `systemd.path` на `/sys/class/net/$ethInterfaces*/carrier` (`PathChanged`) как первый сигнал
      (физическое состояние кабеля).
- [ ] NetworkManager Dispatcher script (`/etc/NetworkManager/dispatcher.d/`) на события
      `up`/`down`/`address-change` для оценки реального default-route по проводу.
- [ ] Скрипт оценки: `ip route get 1.1.1.1` (или самый приоритетный default) → outgoing интерфейс из
      `ethInterfaces`. Эхо в зависимость (`systemd.path`/unit), что кабель есть только если есть
      default-route по проводу.
- [ ] Многодомная коррекция: default-route по Wi-Fi НЕ должен считаться проводным аплинком; если
      есть и провод, и Wi-Fi, предпочтение отдаётся проводу (приоритет/metric).
- [ ] Гонка «кабель дёрнули в момент перехода»: таймаут и повторная оценка перед фиксацией
      состояния; переход в `ap` откладывается, пока проводной default-route не подтверждён повторно.
- [ ] Тест на скрипт оценки (mock интерфейсов/маршрутов), без реального железа.

## Критерий готовности (Definition of Done)

- [ ] Нода переходит в `ap` только когда `ip route get` по проводу реально даёт интернет, и
      возвращается в `client` при его потере, без ручных действий и без ложных срабатываний на
      событие «кабель вставлен, а интернета ещё нет».
- [ ] Скрипт оценки покрыт тестом на смоделированных маршрутах.
