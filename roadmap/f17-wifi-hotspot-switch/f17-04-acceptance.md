# f17-04. Приёмка на многодомной ноде

Живая проверка полного цикла переключения на ноде с проводным Ethernet (`enp3s0`) и Wi-Fi
(`wlp2s0`): вставка/выдёргивание провода переключает режим, isecure: в любой момент активно ровно
одно состояние.

Движет [F17 — динамический режим ноды: Ethernet → Wi-Fi точка доступа](./README.md).

## Контекст

До сих пор ноды проекта были Wi-Fi-only (см. `f1-03`/`DEPLOYMENT.md`). F17 рассчитан на
**многодомную** ноду, которая уже промоделирована в
[`profiles/tcp-gateway/config.nix`](../../profiles/tcp-gateway/config.nix) (`enp3s0` провод +
`wlp2s0` Wi-Fi). Приёмка проводится на такой ноде (или тестовой сборке с виртуальным/вторым
аплинком).

## Что сделать

- [ ] Включить `lattice.hotspot-switch.enable = true` на целевой ноде (новый age-секрет пароля
      hotspot, если `hotspot-password.age` не подходит по SSID/паролю).
- [ ] Проверить цикл: провод вставлен → нода раздаёт Wi-Fi (клиент подключается, получает IP, NAT
      в интернет), Wi-Fi-STA выключен. Провод выдернут → нода возвращается в клиент Wi-Fi.
- [ ] Проверить гонки: выдёргивание/вставка провода в момент перехода, потеря default-route при
      вставленном кабеле, повторная вставка без интернета.
- [ ] Проверить переживание reboot: после перезагрузки нода в корректном состоянии (если провод
      вставлен — AP, иначе — client); impermanence не ломает состояние.
- [ ] Записать результат и любые ручные шаги, которых не хватило в доке (по практике `f1-03`),
      в README задачи/фичи и `DEPLOYMENT.md` при необходимости.

## Критерий готовности (Definition of Done)

- [ ] Полный цикл вставка/выдёргивание провода проходит без ручных действий, CLI-проверками
      подтверждено ровно одно активное состояние (STA **или** AP), без одновременного линка.
- [ ] Переживает reboot и гонки кабеля; результат зафиксирован в документации.
