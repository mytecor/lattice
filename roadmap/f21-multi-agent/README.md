# F21. Multi-agent

Автономное выполнение фичи иерархией Git-задач без A2A. У каждого исполнителя своя задача и
рабочая память; дочерняя работа переживает сессию родителя. Фича объединяет задачи на уровне
файлов, а рабочие ветки создаются только под задачи.

Соответствует [вехе 21](./../../ROADMAP.md#f21-multi-agent). Зависит от
[F19](./../f19-agent-execution-loop/README.md), [F20](./../f20-planning-loop/README.md),
[F22](./../f22-git-trunk-review/README.md) и [F23](./../f23-distributed-coordination/README.md).
Полные требования — в [AGENT_WORKFLOW.md](./../AGENT_WORKFLOW.md).

**Статус:** не начата. Прежний вариант nested ephemeral children с прямым ACP и временем жизни
не дольше root заменён этой постановкой; это изменение плана, а не готовой реализации.

## Задачи

- [f21-01](./f21-01-hierarchical-execution.md) — готовые задачи, эскалация и lifecycle фичи.

## Критерий готовности

- Распределённые `agentd` обнаруживают готовые задачи через Git и meshbus, запускают через r1s
  и восстанавливают контекст без долговременного реестра контейнеров/ACP-сессий в файлах задач.
- Зависимые задачи стартуют после принятия предшественника в `main`; проблемы будят родителя,
  который решает их или обобщает для следующего уровня. Независимая работа продолжается.
- Docs-задача на фичу сверяется с итоговой реализацией; отдельный reviewer принимает фичу.
  Открытые проблемы, цикл доработки, пауза и отмена не приводят к ложному завершению или удалению.
- Потеря root-сессии не останавливает работу; незавершённая задача продолжается другим
  исполнителем после согласованного освобождения права и учёта r1s lease.

## Ограничения

У `taskd` только локальный CLI, у r1s только runtime. Руководитель меняет своё поддерево в
пределах поручения, но не исходные требования. Жёсткого универсального лимита review/fix-циклов
нет; явная блокировка поднимается по иерархии. Технические timeout одного запуска не должны
подменять завершение задачи. Необходимые эксплуатационные пределы ещё нужно конкретизировать.
