# Исполнение иерархии и lifecycle фичи

Фича: [F21](./README.md). Контракт задаётся [F20](./../f20-planning-loop/README.md), принятие —
[F22](./../f22-git-trunk-review/README.md), право исполнения — [F23](./../f23-distributed-coordination/README.md).

## Что сделать

- [ ] Перенести host-reconciliation в `agentd`: повторный обход Git при старте/восстановлении,
      реакция на изменения `git-watchd` через meshbus и запуск каждого готового узла.
- [ ] Различать изменения требований, прогресса и посторонних файлов, не перезапуская работу
      только из-за нового общего HEAD. Готовность зависимости наступает после принятия в `main`.
- [ ] Восстанавливать сессию из поручения, памяти и опубликованных веток. Проверить, что
      остановка root не отменяет потомков и не теряет их результаты.
- [ ] При проблеме запустить непосредственного родителя; записывать решение или обобщённую
      эскалацию. Вопрос человеку хранить до обращения к root, не блокируя независимые задачи.
- [ ] Связать системные review-задачи и независимые checks с кандидатами F22; замечания
      возвращать автору в ту же задачу, без обязательного лимита циклов.
- [ ] Выполнить docs-задачу и итоговое review фичи. При замечаниях оформить доработку и безопасное
      отключение по плану; при отсутствии плана поднять вопрос до человека.
- [ ] Пауза разрешает публикацию checkpoint, но останавливает новые исполнения и принятия.
      Отмена сохраняет принятый код; откат требует отдельной задачи. Учесть гонки с текущим merge.
- [ ] После принятия всей фичи удалить её рабочие файлы отдельным контролируемым изменением;
      до этого сохранять завершённые задачи и связи между ними.

## Критерий готовности

- [ ] Фича с параллельными задачами, docs, review и эскалацией проходит полный цикл без A2A.
- [ ] Recovery после пропущенного события, рестарта и потери ноды не теряет готовую работу;
      возврат старого исполнителя не позволяет принять устаревший результат.
- [ ] Пауза, отмена, блокировка и провал итогового review не удаляют незавершённую фичу.
