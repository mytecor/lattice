# План по фичам

Второй уровень роадмапа: конкретные фичи, из которых складывается сеть. Каждая фича — это
самостоятельная вертикаль с задачами и критерием готовности. Верхнеуровневая картина — в
[VISION.md](./VISION.md), отдельные задачи — в [`tasks/`](./tasks/README.md).

## Как читать

- Фичи упорядочены по зависимостям, а не по календарю.
- Каждая фича ссылается на свои задачи в [`tasks/`](./tasks/README.md).
- Незакрытые вопросы ждут в [`BACKLOG.md`](./BACKLOG.md).

---

## F1. Одна железная нода в работе

Первая веха: проект перестаёт быть только проектом. Нода на Intel N100 ставится с нуля,
переживает перезагрузку и сама применяет коммит из `main`.

Задачи: [f1-01](./tasks/f1-01-assemble-base-profile.md),
[f1-02](./tasks/f1-02-unify-module-profile-model.md),
[f1-03](./tasks/f1-03-bootstrap-intel-n100.md),
[f1-04](./tasks/f1-04-verify-comin-github.md).

**Критерий готовности:** узел установлен с нуля по документации, переживает перезагрузку и
самостоятельно применяет коммит из `main` без участия администратора.

**Осознанно откладываем (до F5):** вторую ноду, radicle-remote в comin, реальные секреты.

---

## F2. Reticulum поверх TCP/IP и удалённый доступ

Узлы связываются через интернет, а не только в LAN, и доступны администратору по RNS-адресу
даже за NAT.

Задачи: [f2-01](./tasks/f2-01-reticulum-tcp-interfaces.md),
[f2-02](./tasks/f2-02-define-entry-points.md),
[f2-03](./tasks/f2-03-second-node-rnsh.md),
[f2-04](./tasks/f2-04-rnsh-nat-access.md).

**Критерий готовности:** с ноутбука через rnsh открывается shell на узле за NAT, связь переживает
смену IP на стороне клиента.

---

## F3. Секреты и идентичность узла

Безопасность сети держится на ключах, а не на закрытости конфигов. Секреты уходят из
репозитория, появляется процедура bootstrap, ротации и отзыва.

Задачи: [f3-01](./tasks/f3-01-secrets-tool.md),
[f3-02](./tasks/f3-02-node-identity.md),
[f3-03](./tasks/f3-03-secret-bootstrap.md),
[f3-04](./tasks/f3-04-replace-dummy-secrets.md),
[f3-05](./tasks/f3-05-key-rotation.md).

**Критерий готовности:** репозиторий можно опубликовать целиком, и это не даёт доступа ни к
одному узлу.

---

## F4. Полезная нагрузка

Узел перестаёт быть только участником сети: несёт сервисы, реплику кода, вычисления и
хранилище.

Задачи: [f4-01](./tasks/f4-01-radicle-seed-comin.md),
[f4-02](./tasks/f4-02-app-services-profile.md),
[f4-03](./tasks/f4-03-shared-storage-compute.md).

**Критерий готовности:** конфигурация сети распространяется между узлами без GitHub, и на узлах
работает хотя бы один прикладной сервис, доступный через шлюз.

---

## F5. Внешние узлы

Граница узла чистая: конфигурация может жить вне этого репозитория, а сеть — принять узел без
раскрытия чужих секретов.

Задачи: [f5-01](./tasks/f5-01-external-node-repo.md),
[f5-02](./tasks/f5-02-trust-policy.md),
[f5-03](./tasks/f5-03-contributing-guide.md).

**Критерий готовности:** узел из внешнего репозитория участвует в сети и не имеет доступа к
секретам других узлов.

---

## F6. Радио и mesh

Работа на узком канале: LoRa/RNode как ещё один интерфейс Reticulum.

Задачи: [f6-01](./tasks/f6-01-rnode-lora-interfaces.md),
[f6-02](./tasks/f6-02-narrow-channel-profile.md),
[f6-03](./tasks/f6-03-msgbus-module.md).

**Критерий готовности:** два узла обмениваются данными по радио при отключённом интернете.

## Текущие расхождения с документацией

Узкие места, которые уже видны и тормозят конкретно F1–F3. Часть из них решается внутри задач
выше, часть — быстрые фиксы:

- `modules/README.md` и `profiles/README.md` описывают каждый каталог как самостоятельный flake с
  `nixosModule`, но на диске лежат только `config.nix`/`options.nix`, а `nodes/example` подключает
  их как `flake = false`. См. [f1-02](./tasks/f1-02-unify-module-profile-model.md) и
  [BUILD_MODEL.md](../../BUILD_MODEL.md) — решение №1 согласовано.
- `profiles/base` упомянут в README и DEPLOYMENT.md, но не существует — создаётся в
  [f1-01](./tasks/f1-01-assemble-base-profile.md).
- `profiles/rns-server` поднимает только `AutoInterface` со `discovery_scope = "link"`, то есть
  работает в одном broadcast-домене — расширяется в [f2-01](./tasks/f2-01-reticulum-tcp-interfaces.md).
- В `nodes/example/flake.nix` секция profiles закомментирована — включается в
  [f1-01](./tasks/f1-01-assemble-base-profile.md).
- Секреты-заглушки (`dummy-key-for-vm`, `fakeWirelessSecret`) — заменяются в
  [f3-04](./tasks/f3-04-replace-dummy-secrets.md).
