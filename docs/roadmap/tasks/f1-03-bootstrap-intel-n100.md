# Создать и развернуть `mytecor-homelab` на Intel N100 с нуля

Фича: [F1 — одна железная нода](../features/f1-one-node.md).

## Контекст

Первая веха: проект перестаёт быть только проектом. Первой реальной нодой будет
`mytecor-homelab` на Intel N100. Нужно создать её конфигурацию, пройти путь установки по
`DEPLOYMENT.md` и зафиксировать все ручные шаги, которых в документации не хватило.

До миграции эта физическая машина работает с hostname `byurik`. В результате миграции она получает
hostname и имя конфигурации `mytecor-homelab`; отдельная нода `byurik` не создаётся.

На исходной системе нет данных, требующих сохранения. Для этой миграции backup текущего root не
делается, а существующая Reticulum identity считается одноразовой. Откат выполняется повторной
чистой установкой, а не восстановлением исходной системы.

У ноды нет Ethernet или другого резервного подключения. Wi-Fi должен входить в установленную
конфигурацию заранее: без него `comin` не сможет продолжить получать обновления после установки.

## Что сделать

- [x] Создать `nodes/mytecor-homelab/` по образцу `nodes/example/`.
- [x] Добавить `nixosConfigurations.mytecor-homelab` и задать hostname `mytecor-homelab`.
- [x] Подключить стираемый root через общий модуль `modules/ephemeral-root`, оставив разметку
      диска и список сохраняемых данных на уровне `nodes/mytecor-homelab/`.
- [x] Перечислить в persistence ключ secrets и состояние, необходимое для административного
      доступа; не переносить существующую Reticulum identity.
- [x] Подключить реальные SSID и пароль Wi-Fi через runtime-файлы `agenix`, не добавляя открытые
      значения в репозиторий или Nix store.
- [ ] До разрушительного шага удалённо передать ключ secrets и проверить, что целевая конфигурация
      содержит Wi-Fi-профиль, SSH authorized keys и системный SSH-сервис.
- [ ] Настроить предсказуемое обнаружение после перезагрузки: DHCP reservation либо mDNS-имя
      `mytecor-homelab.local`.
- [x] До установки собрать конфигурацию и убедиться, что Wi-Fi-профиль входит в system closure.
- [ ] Развернуть `mytecor-homelab` на Intel N100 с нуля через существующий SSH-канал строго по
      `DEPLOYMENT.md`, не настраивая Wi-Fi или доступ на локальной консоли.
- [ ] Записать каждый ручной шаг, отсутствующий в документации.
- [ ] Дополнить `DEPLOYMENT.md` обнаруженными шагами.
- [ ] Проверить на установленной системе Wi-Fi, DNS, доступ к GitHub и работу `comin`.
- [ ] Проверить, что узел переживает перезагрузку (ephemeral-root + impermanence сохраняют
      нужные данные), автоматически возвращает Wi-Fi и продолжает получать обновления.

## Критерий готовности

- [ ] `mytecor-homelab` установлен с нуля по документации человеком вне проекта.
- [ ] После запуска миграции штатный путь не требует действий на локальной консоли.
- [ ] После перезагрузки узел без ручного вмешательства подключается к Wi-Fi.
- [ ] После перезагрузки `comin` получает `main` через единственный Wi-Fi-канал.
- [ ] Временное состояние стираемого root исчезает после перезагрузки, а ключ secrets и
      административный доступ продолжают работать через `/persist` и декларативную конфигурацию.
- [ ] Узел возвращается в рабочее состояние с сохранёнными данными `/persist`.
