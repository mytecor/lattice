# Проверить доступ по rnsh к узлу за NAT

Фича: [F2 — Reticulum поверх TCP/IP](../features/f2-reticulum-tcp.md).

## Контекст

Ключевой результат F2: с ноутбука через rnsh открывается shell на узле, который находится за
NAT (без белого IP), и связь переживает смену IP на стороне клиента.

## Что сделать

- [ ] С ноутбука открыть shell на узле за NAT через rnsh по RNS-адресу.
- [ ] Сменить IP на стороне клиента и убедиться, что rnsh-сессия/восстановление работает.
- [ ] Зафиксировать, какой транспорт и точка входа обеспечивают связь (см. f2-02).

## Критерий готовности

- [ ] Shell на узле за NAT доступен через rnsh без белого IP и без проброса портов.
- [ ] Связь переживает смену IP на клиенте.

## Затрагиваемые файлы / слои

- `profiles/rnsh`
- `nodes/` (узлы сети)
