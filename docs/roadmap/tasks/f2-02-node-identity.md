# Определить идентичность узла

Фича: [F2 — секреты и идентичность](../features/f2-secrets-identity.md).

## Контекст

Нужно решить, что является идентичностью узла: отдельные ключи на каждую подсистему или один
host-ключ, из которого выводятся остальные. От этого зависит bootstrap, ротация и политика
доверия.

## Что сделать

- [x] Выбрать модель идентичности узла (один host-ключ или несколько).
- [x] Оформить в `ARCHITECTURE.md`: что является идентичностью, как выводятся производные ключи.
- [x] Согласовать модель ключа с `agenix`, выбранным в [f2-01](./f2-01-secrets-tool.md).

## Критерий готовности

- [x] Модель идентичности описана в `ARCHITECTURE.md` и совместима с выбранным инструментом.

## Результат

Стабильное имя из `nodes/<name>` обозначает логическую ноду, но само по себе не аутентифицирует
её. К имени привязывается набор независимых публичных идентификаторов, каждый со своим назначением
и жизненным циклом:

| Ключ / идентификатор | Назначение | Правило |
| -------------------- | ---------- | ------- |
| age recipient ноды | Расшифрование `agenix` secrets | Отдельный постоянный ключ; единственный закрытый ключ, передаваемый при bootstrap |
| SSH host key | Аутентификация OpenSSH-сервера | Генерируется и хранится отдельно от age-ключа |
| Reticulum/rnsh identities | Адреса и аутентификация RNS-сервисов | Отдельны от системных ключей; постоянны, когда стабильный destination входит в контракт сервиса |
| Radicle key | Идентичность и подпись Radicle | Отдельна от age, SSH и Reticulum |

Закрытые ключи не выводятся из общего мастер-ключа и не переиспользуются между разными границами
доверия. После bootstrap `agenix` может доставлять зашифрованные сервисные ключи; ключи, которые
безопасно создать на самой ноде, могут вместо этого генерироваться локально и сохраняться в
`/persist`. Публичные ключи, fingerprints, destination hashes и их привязку к имени ноды можно
хранить в Git.

Reticulum Network Identity, если она будет включена в F3, является общей идентичностью домена
сети, а не индивидуальной идентичностью ноды. Администраторский SSH-ключ — идентичность оператора и
recovery recipient, но также не идентичность ноды.
