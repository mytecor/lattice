# Профиль прикладных сервисов поверх `tcp-gateway`

Фича: [F4 — полезная нагрузка](../FEATURES.md).

## Контекст

Узел перестаёт быть только участником сети: должен нести сервисы владельца, доступные через
шлюз. `profiles/tcp-gateway` уже автоматически настраивает роутинг для активных TCP/HTTP-профилей;
нужен профиль для прикладных сервисов владельца поверх него.

## Что сделать

- [ ] Определить профиль (или пример) прикладного сервиса поверх `tcp-gateway`.
- [ ] Подключить как минимум один сервис, доступный наружу через шлюз.
- [ ] Проверить доступ к сервису с внешней машины.

## Критерий готовности

- [ ] На узле работает прикладной сервис, доступный через шлюз (`tcp-gateway`).

## Затрагиваемые файлы / слои

- `profiles/tcp-gateway`, `profiles/` (новый прикладной профиль)
- `nodes/`
