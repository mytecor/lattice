# Профиль прикладных сервисов поверх `tcp-gateway`

Фича: [F4 — полезная нагрузка](../features/f4-payload.md).

## Контекст

Узел перестаёт быть только участником сети: должен нести сервисы владельца, доступные через
шлюз. `profiles/tcp-gateway` уже автоматически настраивает роутинг для активных TCP/HTTP-профилей;
нужен профиль для прикладных сервисов владельца поверх него.

## Что сделать

- [x] Определить профиль (или пример) прикладного сервиса поверх `tcp-gateway`.
- [x] Подключить как минимум один сервис, доступный наружу через шлюз.
- [x] Проверить доступ к сервису с внешней машины.

## Критерий готовности

- [x] На узле работает прикладной сервис, доступный через шлюз (`tcp-gateway`).

## Результат

Выполнено 2026-09-05. Профиль `profiles/app-services` импортирует `tcp-gateway` и добавляет
`http://status.<node>.<domain>/`. Статический JSON endpoint обслуживает сам Caddy через `respond`:
для него не запускается отдельный backend и не открывается внутренний порт. Если
`networking.domain` не задан, используется `lattice` и HTTP site label; Caddy не пытается получить
публичный сертификат для внутреннего TLD. То же правило применено к автоматически создаваемым
routes Radicle и `rns-server`.

`nix flake check path:. --no-build --all-systems` прошёл на Mac. На x86_64 homelab собраны
`checks.x86_64-linux.app-services` и полный system closure, после чего конфигурация активирована в
режиме `test`. Запрос из Yaak на `http://192.168.60.168/` с заголовком
`Host: status.mytecor-homelab.lattice` вернул:

```json
{"node":"mytecor-homelab","service":"lattice-node-status"}
```

Одновременно проверено, что Nginx отсутствует, отдельного backend listener нет, `radicle-httpd`
доступен через HTTP route Caddy, а failed systemd units отсутствуют.
