# Ввести `agenix` для управления секретами

Фича: [F2 — секреты и идентичность](../features/f2-secrets-identity.md).

## Контекст

Инвариант: «конфигурация публична, секреты — нет», безопасность держится на ключах. Для Lattice
выбран `agenix`: он хранит зашифрованные age-файлы в репозитории и предоставляет сервисам пути к
расшифрованным runtime-файлам.

## Что сделать

- [x] Выбрать `agenix` для сценария Lattice (pull-based, ключи на узле).
- [x] Зафиксировать выбор и границы решения в `ARCHITECTURE.md`.
- [x] Подключить `agenix` как input и NixOS-модуль.
- [x] Добавить первые зашифрованные Wi-Fi secrets для `mytecor-homelab` и проверить их пути в
      конфигурации ноды.

## Критерий готовности

- [x] Инструмент выбран и задокументирован в `ARCHITECTURE.md`.
- [x] Базовая схема шифрования секретов работает в сборке.

## Затрагиваемые файлы / слои

- `modules/`, `profiles/` (новый профиль секретов)
- `ARCHITECTURE.md`

## Открытые вопросы

Какой закрытый ключ использует нода для расшифрования agenix — отдельный age-ключ или SSH host
key — решается в [f2-02](./f2-02-node-identity.md). Минимальная рабочая интеграция для Wi-Fi
`mytecor-homelab` нужна до её развёртывания в [f1-03](./f1-03-bootstrap-intel-n100.md).
