# Добавить TCP-интерфейсы Reticulum в `rns-server`/`profiles/rns-server`

Фича: [F3 — Reticulum поверх TCP/IP](../features/f3-reticulum-tcp.md).

## Контекст

До этой задачи `profiles/rns-server` включал только `AutoInterface` со scope `link`. Типы
`TCPClientInterface`/`TCPServerInterface` и базовые поля уже существовали в модуле, но профиль их
не использовал, а обязательные параметры не проверялись. Задача готовит TCP-конфигурацию;
реальная интернет-топология определяется в f3-02.

## Что сделать

- [x] Довести типизированные TCP-опции в `modules/rns-server`: обязательные адреса и порты,
      положительный лимит соединений и отдельный `openFirewall` для сервера.
- [x] Заполнить их дефолтами в `profiles/rns-server`.
- [x] Проверить, что конфиг Reticulum (typed-генерация ConfigObj) корректно включает TCP-интерфейсы
      при сборке.

## Критерий готовности

- [x] Узел с `profiles/rns-server` поднимает TCP-интерфейс, а не только `AutoInterface`.
- [x] Конфиг генерируется через typed-генерацию без ручных правок.

## Результат

Выполнено 2026-09-04. Профиль добавляет `TCP Server` (`0.0.0.0:4242`, до 64 соединений) и
отключённый `TCP Uplink` с портом 4242; адрес uplink задаётся при выборе точки входа. Все дефолты
можно переопределить. Профиль включён в `example` через корневой flake; конфигурация рабочей
`mytecor-homelab` не менялась. Входящий порт открывается явно через `openFirewall`, transport
routing — через `reticulum.enable_transport`; публичная доступность не предполагается автоматически.

Опции проверяют обязательные TCP-поля, диапазон портов 1–65535, непустые адреса без пробелов и
переносов строк, положительный `max_connections`. `openFirewall` не попадает в ConfigObj и не
открывает порт отключённого интерфейса. Переопределение TCP-полей через `extraConfig` и неподдерживаемые
TCP-алиасы отклоняются при проверке конфигурации.

Проверки:

- `nix flake check --all-systems --no-build` — успешно для всех выходов, включая `example`, homelab
  и новый `checks.x86_64-linux.rns-tcp`. Полная сборка Linux-систем локально не выполнялась.
- Проверка `tests/rns-tcp.nix` собрана с нативным `pkgs` на macOS: NixOS evaluation проверяет
  дефолты, отрицательные случаи и firewall; независимый ConfigObj parser проверяет точные
  сгенерированные байты профиля, клиента и переопределённых настроек. Эта же проверка входит в CI.
- Из закреплённого `rns-rs` commit `7743a77938a03defbbace03913117c03db18ccdf` собран пример `rnsd`.
  Два локальных процесса прочитали Nix-сгенерированные конфиги без ручных правок; сервер слушал
  loopback на свободном TCP-порту, клиент установил соединение. AutoInterface и shared instance
  были отключены через Nix-опции для изоляции локального теста; оба процесса завершены после проверки.

Проверка через интернет, systemd на реальной ноде и rnsh за NAT впоследствии выполнена в F3-04.
