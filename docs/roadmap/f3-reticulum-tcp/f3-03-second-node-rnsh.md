# Поднять второй узел; включить `profiles/rnsh` на обоих (отменена)

Фича: [F3 — Reticulum поверх TCP/IP](./README.md).

**Статус:** отменена 2026-09-05. Вторая постоянная NixOS-нода не входит в актуальный план.

## Контекст

Первоначально для проверки межузловой связи планировались две постоянные NixOS-ноды с
`profiles/rnsh`. Фактический критерий F3 проверен между homelab и операторским Mac через
публичные TCP peers, включая смену клиентской сети. Отдельная постоянная нода для этого не нужна.

## Решение

- [x] Исключить вторую постоянную NixOS-ноду из F3.
- [x] Использовать Mac как отдельного Reticulum-участника и rnsh-клиента.
- [x] Проверить доступ к homelab через публичные TCP peers без общей LAN.

## Критерий готовности

- [x] Задача явно закрыта как отменённая и больше не блокирует F3.

## Промежуточный результат на 2026-09-04

Homelab подключён к Sydney/ReticulumNet и запускает rnsh от отдельного пользователя с явным
allowlist. Mac с Python RNS 1.5.2 выступает вторым тестовым участником: команда `hostname`
выполняется на homelab через публичный маршрут. Чужая identity получает явный отказ.
`/var/lib/rns` и `/var/lib/rnsh` сохранены в `/persist`; destination слушателя не менялся
при повторных активациях/перезапусках.

2026-09-05 после переключения Mac на мобильный hotspot повторный доступ к homelab прошёл с
прежними identity и destination. Клиент использовал только публичные TCP uplink, LAN discovery
был выключен. Решением владельца проекта создание второй постоянной ноды отменено; listener на
Mac для критерия F3 не требуется.
