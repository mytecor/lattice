# Lattice

Lattice - проект для построения сети связанных нод, которые могут обмениваться данными, предоставлять удаленный доступ и хранить код без зависимости от центральной инфраструктуры.

Каждая нода является самостоятельным узлом сети и может работать в условиях ограниченной или нестабильной связности. Узлы объединяются через Reticulum, а поверх этой сети предоставляется удаленный shell-доступ.

Этот репозиторий является точкой сборки сети. Один корневой Nix flake собирает локальные слои и
конфигурации нод, а также служит источником pull-based обновлений для узлов.

## Цели проекта

- Создать автономную сеть связанных вычислительных узлов
- Обеспечить связь между нодами без обязательного центрального сервера
- Дать администраторам безопасный доступ к узлам через Reticulum rnsh
- Хранить и распространять исходный код через распределенный Git
- Сделать конфигурацию узлов воспроизводимой и управляемой
- Поддерживать единый flake, описывающий состав сети и подключение репозиториев нод

## Статус

Первая физическая нода `mytecor-homelab` развёрнута на Intel N100. Она автоматически подключается
к Wi-Fi, принимает key-only SSH, использует стираемый Btrfs root и применяет `main` через `comin`.
Задачи F2 выполнены: определена модель независимых ключей, устранены заглушки, описаны ротация и
отзыв доступа. F3 также завершена: выбраны публичные peers Sydney/ReticulumNet, а на homelab
работает rnsh с авторизацией по identity. После переключения Mac на мобильный hotspot клиент с
прежними identity и destination повторно подключился через публичную сеть без LAN discovery;
сервисы ноды не перезапускались. Вторая постоянная NixOS-нода исключена из плана. В F4 на homelab
работает selective Radicle seed, публичная реплика доступна через независимые seeds, а `comin`
выбирает локальный Radicle remote перед GitHub. После завершения F4 основной маршрут идёт через
F7–F11 — LLM gateway, Pi, caches/artifacts, disposable worker и controller.

- Структура flake для импорта репозиториев нод
- Базовые скрипты установки и первичной настройки
- Примеры конфигураций Reticulum
- Документация по подключению через rnsh
- Описание политики доверия между узлами
- Инструкции по добавлению новой ноды в сеть
- Self-hosted agent runtime с provider-agnostic классами моделей
- Disposable workers и восстанавливаемое выполнение задач
